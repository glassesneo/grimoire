# Review and Generalization Checklist

Read when reviewing or revising an existing text, or before adding a rule to a text that future readers will reuse. Run the Checks in SKILL.md first; the items below add what a review needs beyond them.

## Contract

- Is the reader named, and is it the actual reader rather than a generic one?
- Is the return stated: what the reader decides, does, or produces?
- Is the text designed for the reader-visible form after rendering, expansion, or copying?
- Are the reader's resources and limits accounted for?

## Projection

- Is any concept present only because it is forbidden?
- Does an example expose details that are not part of the reader's task?
- Is a workflow restated that a skill, profile, or stable instruction already provides?

## Layers and placement

- Is on-demand material separated from first-read material?
- Does each item sit in the document or system that owns it?
- For several readers, does any reader see context that is a leak for that reader?

## Return

- Is the required form of the return specified at the needed level of detail?
- Are rationale and tradeoffs inside the artifact only when the return requires a judgment?

## Generalization

Before adding a rule to a reusable text, confirm:

- it applies to every intended reader of that text
- it does not depend on an artifact format the text is not written for
- it does not depend on a runtime or tool the text is not written for
- it can be expressed without naming the example that prompted it
- it does not belong in a more specific document instead

## Review output

Tie each observed issue to a contract part or a projection decision.
